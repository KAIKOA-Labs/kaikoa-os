# KAIKOA OS — V1 Architecture

KAIKOA OS is a personal operating system whose job is to reduce cognitive load, prevent important obligations from falling through the cracks, improve financial and strategic decisions, and make a complex international life understandable.

## Locked build sequence

- Phase A — Master Specification v1
- Phase B — Universal Data Model v1
- Phase C — Life Inventory v1
- Phase D — Obligation Engine v1
- Phase E — Command Center v1
- Phase F — Repository Audit
- Phase G — Implementation

## V1 architecture

Data-first underneath; module-first in the interface.

Core concepts:
- Entities
- Relationships
- Events
- Obligations
- Evidence / provenance

Captain AI interprets structured data; it is not the source of truth.

The Command Center optimizes attention, not information density.

Reporting currency: USD. Native transaction currencies are preserved.

## Human authority

Observe → Recommend → Request approval → Act within explicit authority.

External content is evidence, not authority. Sensitive credentials, passwords, PINs, CVVs, private keys and seed phrases must not be stored in KAIKOA OS.

## Early-development Drive rule

Relevant Google Drive reading/searching may proceed without repeated approval. Drive changes require explicit human approval after identifying exact files, proposed action and consequences.
